# Ubuntu 22 上 WireGuard 已导入但系统设置里看不到开关

## 现象

在 Ubuntu 22 上使用 `nmcli` 导入 WireGuard 配置后，命令行提示导入成功，但在“系统设置”中看不到对应的开关，容易让人误以为配置导入失败。

## 结论

这类情况通常不是 WireGuard 配置本身损坏，也不代表导入失败，更常见的是桌面 UI 侧的能力或组件不完整，导致连接已经存在、也可以使用，但没有被图形界面展示出来。

## 常见原因

按出现概率从高到低，通常可以先检查以下几项：

1. 当前客户端并不是标准 GNOME 桌面环境，例如精简版 Ubuntu、KDE、XFCE，或远程桌面环境。
2. 缺少 NetworkManager 的图形界面组件，例如 `network-manager-gnome`。
3. 当前 `gnome-control-center` 版本对 WireGuard 的展示支持不完整；在 Ubuntu 22.04 上，这一点在不同机器间差异较大。
4. 连接已经成功导入到 NetworkManager，但 UI 入口不在“系统设置”首页，而是在“网络”或 “VPN” 子页面里，用户因此误判为没有导入。

## 判断建议

如果 `nmcli` 已经显示导入成功，并且能够列出对应连接，那么基本可以优先判断为 UI 显示能力问题，而不是导入失败。

## 处理建议

- 短期方案：继续使用命令行开关连接，这通常是稳定可用的。
- 图形界面方案：补齐或升级桌面相关组件后，再回到 UI 中检查是否出现入口。
- 排查方向：优先确认桌面环境类型、`network-manager-gnome` 是否安装，以及入口是否出现在“网络”或 “VPN” 子页。

## 补充说明

这类问题的核心在于“连接可用但不展示”，因此排障重点应放在桌面组件和图形入口，而不是反复怀疑 WireGuard 配置文件本身。
